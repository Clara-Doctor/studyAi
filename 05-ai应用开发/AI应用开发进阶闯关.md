## 阶段一 · RAG：让 AI 懂你的私域数据（第 1~4 关）

### 第 1 关 · 认识 RAG：为什么模型会"一本正经地胡说"
- 🎯 理解 RAG 解决什么：模型不知道**你的**数据（房源、公司文档），硬问就幻觉
- 📖 理论：《AI编程学习路径.md》§1.1（幻觉）、§3.3（上下文工程）
- 🔧 动手（不写代码）：先问 claude "我们 eval-practice-house 项目第 7 条用例的期望朝向是什么"
  ——它答不上来（没读过你的文件）。然后你**手动**把 cases.json 内容粘给它再问——答对了。
  这个"先查资料再回答"的动作，就是 RAG 的全部灵魂
- ✅ 验收：能说出 RAG 五步——**切块 → 向量化 → 存储 → 检索 → 拼进提示词**

### 第 2 关 · 向量与相似度：机器怎么知道两段话"像"
- 🎯 理解 embedding：文字 → 数字向量，语义近 = 向量夹角小（余弦相似度）
- 🔧 动手：用 Python 写 30 行——几条房源描述手工标注标签，
  用关键词重合度模拟"相似度"（`jaccard` 集合相似即可，不需要任何外部服务），
  给定一条新描述，找出最像的 2 条
- ✅ 验收：能回答"为什么 '89平朝南拎包入住' 和 '南北两居 89㎡' 关键词法会失手，
  而语义向量法能救"（提示：同义词）
- ⚠️ 进阶备注：真 embedding 需要 API（Anthropic 官方无 embeddings 接口，
  常用 Voyage/OpenAI 系/本地 sentence-transformers）——你的中转站是否支持要实测，
  不通就先用第 2 关的关键词法把流程跑通，不影响学原理

### 第 3 关 · 搭第一个 RAG：房源 FAQ 问答机器人
- 🎯 端到端：faq.md（自己写 10 条房源问答对）→ 切块 → 检索 top3 → 塞进 prompt → 回答
- 🔧 动手（`rag_bot.py`，结构骨架）：
  ```python
  # 1. 读 faq.md，按 "## " 标题切块 → chunks 列表
  # 2. 用户问题 → 和每个 chunk 算相似度（第 2 关的函数）
  # 3. 取 top3，拼成上下文：
  #    prompt = f"参考以下资料回答，资料里没有就说不知道：\n{top3}\n\n问题：{q}"
  # 4. client.messages.create(...) 常规调用
  ```
- ✅ 验收：问"停车方便吗"能答对；问知识库里**没有**的问题（如"能养宠物吗"），
  它老实说"资料里没有"——**不编**（这是 RAG 的反幻觉红线）

### 第 4 关 · RAG 调优：检索不准，后面全白搭
- 🎯 理解 RAG 的质量瓶颈在**检索**不在生成；学会用评测思路调 RAG
- 🔧 动手：写 5 个"问题→应命中的块"测试对，跑检索命中率；
  然后调三个旋钮各测一次：块切大点/小点、top3 改 top5、关键词改"关键词+重合加权"
- ✅ 验收：用一张小表记录每个旋钮对命中率的影响——**你用第 7 课的评测方法驯服了 RAG**

## 阶段二 · LLM-as-Judge：用模型当裁判（第 5~6 关）

### 第 5 关 · 裁判模式：硬规则判不了的软质量
- 🎯 你的 eval.py 是正则比数字；但"这段回答通不通顺、专业不专业"没有正则可写——
  让另一个模型按**评分量规（rubric）**打分
- 🔧 动手（`judge.py`）：写一个裁判——输入（问题、参考答案、被评答案），
  输出结构化（用你熟悉的工具调用模式！）`{"score": 1-5, "reason": "..."}`
- ✅ 验收：拿它评 extractor 的 3 条真实输出，打分理由具体可查，不是"挺好的"式废话

### 第 6 关 · 裁判也不可靠：校准你的裁判
- 🎯 迁移第 7 课最重要的一句话——**判分器必须先可靠**。裁判模型的坑：
  偏爱长答案（长度偏好）、偏爱排在前面的（位置偏差）、分数量纲漂移
- 🔧 动手：故意给同一份答案换个顺序/凑长再评，观察分数变没变；
  然后上三招校准：rubric 写具体（每档分有明确描述）、评 3 次取中位数、
  A/B 对比式打分（两份答案直接比高低，比绝对打分稳得多）
- ✅ 验收：能说出"什么时候敢信裁判、什么时候必须人工抽查"

## 阶段三 · 生产工程化：从能跑到敢上线（第 7~9 关）

### 第 7 关 · 健壮性三件套：重试、超时、限流
- 🎯 线上 API 必然偶发超时/429/5xx——Demo 和产品的分水岭就是怎么接住它们
- 🔧 动手：给 `extract_listing` 包一层生产外壳（手写 30 行，别引库，看懂原理）：
  指数退避重试（1s→2s→4s，最多 3 次）、设置超时、429 读 retry-after 等待
- ✅ 验收：故意把 BASE_URL 改错制造失败，观察重试日志；能说出哪些错误该重试
  （429/5xx/超时）哪些不该（400 参数错——重试一万次也是 400）

### 第 8 关 · 缓存与降级：省钱和保命
- 🎯 两个生产刚需：同样的问题别重复烧钱（缓存）；主模型挂了别让服务死（降级）
- 🔧 动手：①给 rag_bot 加"问题→答案"内存缓存（dict 就行，体会原理）；
  ②写降级链：opus 超时 → 自动切 haiku → 还不行 → 返回兜底文案
- ✅ 验收：连续问同一个问题，第二次 0 次 API 调用；拔掉主模型，服务仍能给答复
- 📖 呼应：《模型编排详解教程.md》——降级链就是模型编排的容错形态

### 第 9 关 · 监控与数据飞轮：上线只是开始
- 🎯 生产 AI 服务必须记账（每次调用：输入/输出/token/耗时/成败），
  而且**线上 bad case 是最好的评测集养料**——这个循环叫数据飞轮
- 🔧 动手：给 extractor 加一行"调用日志追加写 csv"；跑 20 条后读日志，
  挑出最差的 2 条 → 人工标注 → 追加进 cases.json → 重跑评测
- ✅ 验收：完成一次完整飞轮：线上日志 → bad case → 评测集 → 提分。
  能说出为什么这循环是 AI 产品和传统软件最大的差别

## 阶段四 · 选型与视野（第 10~11 关）

### 第 10 关 · 三条路怎么选：提示词 vs RAG vs 微调
- 🎯 面试高频题：教 AI 私有知识/私有能力，三条路的成本、时效、效果对比
- 🔧 动手（纯思考题）：给三个场景写选择+理由——
  ①"客服机器人要懂我们公司 500 页产品手册"；②"提取器总把'南北通透'写成'朝南'，
  规则写了十条还漏"；③"每周更新的价格表要能被问到"
- ✅ 验收：结论能落地成一句决策口诀（参考：知识常变→RAG；格式习惯顽固→提示词/schema；
  任务模式固定且量大→才考虑微调）

### 第 11 关 · 多模态初体验（选修）
- 🎯 图片也能进模型——房源照片 → 结构化描述
- 🔧 动手：用 messages.create 的 image 内容块（base64）传一张房源图，
  让模型输出 `{"户型描述": "...", "装修风格": "..."}`
- ✅ 验收：能说出多模态对你业务的一个真实落地点（如：租客拍照自动填房源表单）

## 🎓 毕业项目：把 extractor.py 升级成"生产级提取服务"

综合全部 11 关，把课程最初那个 87 分的练习项目，改造成一个像样的"产品"：

1. **健壮**（第 7 关）：重试/超时/降级齐全
2. **省钱**（第 8 关）：缓存 + 常规请求走低档模型、疑难走高档（模型编排）
3. **可信**（第 5、6 关）：线上抽样 → 裁判打分 → 可疑的人工复核队列
4. **可观测**（第 9 关）：调用日志 csv + 每周 bad case 回收进 cases.json
5. **有据可查**（第 1~4 关）：附一份 README 说明"这个服务怎么用、边界在哪、挂了怎么办"

**毕业标准**：别人拿到你的文件夹，不看代码也知道怎么用、坏了找谁、
质量怎么保证——这就是"工程师做的 AI"和"玩具 AI"的区别。
