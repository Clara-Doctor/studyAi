# 模型编排详解教程 —— 让贵的干少的

> 定位：《ClaudeCode深度用法与结对开发闯关.md》第 19 关配套教材。
> 一句话目标：同一个 Agent 循环，装不同的"引擎"（模型）价格差 **5 倍**——
> 本教程教你给活分档、让贵模型只干真正值钱的活。
> 前提：用过 `agent_lib.py`（第 3 课）；最好跑过一次 `eval-practice-house/eval.py`（第 7 课）。

---

## 第 0 章 · 为什么：同一台车，不同发动机

官方价目（每 100 万 token，2026-10 实查，输入/输出）：

| 模型档位 | 模型 ID | 价格 | 相对成本 |
|---|---|---|---|
| 旗舰 | `claude-fable-5` | $10 / $50 | 10× |
| 大模型（opus 系） | `claude-opus-4-8` | $5 / $25 | 5× |
| 中档（sonnet 系） | `claude-sonnet-5` | $3 / $15 | 3× |
| 小模型（haiku 系） | `claude-haiku-4-5` | $1 / $5 | **1×（基准）** |

关键事实：**Agent 的循环结构完全一样**——小模型也照样会用工具、会多轮、会写代码，
差别在"想得深不深"。所以编排的本质是：

> **贵的干"想"的活，便宜的干"跑腿"的活。**
> 类比：公司不会让 CEO 复印文件，也不会让实习生定年度战略。

## 第 1 章 · 分工原则：什么活配什么档

| 活的类型 | 配什么 | 例子 |
|---|---|---|
| **规划、拆解、定方案** | 贵（opus/fable） | "把整个需求拆成任务清单"、架构设计 |
| **审查、判断、把关** | 贵 | 评审 AI 写的代码对不对、判分、质量抽检 |
| **难的推理/调试** | 贵 | 疑难 bug 定位、复杂算法 |
| **按图施工（执行明确计划）** | 便宜（haiku） | 计划已写好，照着一步步改文件 |
| **批量重复的简单判断** | 便宜 | 1000 条评论分类、字段抽取、格式转换 |
| **日常问答、总结** | 中档（sonnet） | 一般写码、写文档 |

记忆口诀：**一次性、想不通会全盘皆输的活给贵的；跑量、有尺子兜底的活给便宜的。**
（"有尺子兜底"= 你有 eval 能立刻发现它干砸了——这就是敢用便宜的底气。）

## 第 2 章 · 操作一：换挡实验（10 分钟，先找体感）

第一步小改造：把 `agent_lib.py` 的模型从常量改成参数（就改两行）：

```python
# 原来：MODEL = "claude-opus-4-8"（写死的全局常量）
# 改成：默认值不变，但允许调用时换挡
MODEL = "claude-opus-4-8"

def run_agent(system_prompt, task, tools=None, max_turns=12, verbose=True,
              tool_executor=None, model=None):        # ← 加 model 参数
    model = model or MODEL                            # ← 没指定就用原来的
    ...
    "model": model,                                   # ← 循环里原来写 MODEL 的地方改成 model
```

然后同一个任务跑两次，记录对比：

```python
task = "读 advanced-agent-lab 文件夹，总结每个文件讲什么"
run_agent(SYSTEM, task, tools=FS_TOOLS, model="claude-opus-4-8")   # 第 1 次
run_agent(SYSTEM, task, tools=FS_TOOLS, model="claude-haiku-4-5")  # 第 2 次
```

| 记录项 | opus | haiku |
|---|---|---|
| 结论质量（1~5 分你的主观分） | | |
| 有没有用错工具/卡住 | | |
| 总 token 消耗（verbose 输出里有） | | |

> ⚠️ 中转站注意：先发一个最小请求确认中转站支持该模型 ID
>（报 `model not found` 就降档换 `claude-sonnet-5` 或 `claude-sonnet-4-6` 再试）。

## 第 3 章 · 操作二：两段式流水线（本关核心：贵出计划，便宜执行）

```python
# two_stage.py —— 大模型当架构师出计划（跑 1 次），小模型当施工队照做
from agent_lib import run_agent, FS_TOOLS   # 你课程里的教学版框架

PLANNER_SYSTEM = """你是资深架构师。收到需求后输出一份施工计划：
- 要改哪些文件、每个文件做什么
- 步骤清单，每步可独立验证
- 不写代码本身，只写计划"""

EXECUTOR_SYSTEM = """你是施工队。严格按给定的计划逐步执行。
每完成一步在输出里标注 ✓。计划没写的不要做，计划有冲突就停下来报告。"""

def two_stage(requirement: str):
    # 第 1 段：贵的上场，只出文字计划（没有工具，纯思考，1 次调用）
    plan = run_agent(PLANNER_SYSTEM, requirement,
                     tools=None, max_turns=2, verbose=False,
                     model="claude-opus-4-8")

    # 第 2 段：便宜的上场，吃计划干活（要用文件工具，多轮循环）
    result = run_agent(EXECUTOR_SYSTEM, f"按此计划执行：\n{plan}",
                       tools=FS_TOOLS, max_turns=12, verbose=False,
                       model="claude-haiku-4-5")
    return result
```

为什么省钱：贵模型**只跑 1 次纯思考**（无工具循环）；费轮次的文件操作全部交给
1/5 价格的模型。质量靠前面那段保证——计划是贵的出的，执行者照图施工不易跑偏。

> 🔍 对照你已经学过的：这就是"指挥官-工人"模式（第 6 课）的**经济版**——
> 指挥官用贵的，工人用便宜的。第 6 课教的是"派活隔离上下文"，本关多了一层
> "派活顺带选档位"。

## 第 4 章 · 操作三：按任务路由（进阶概念，知道即可）

做成线上服务时的最终形态：**来一个请求先用便宜模型当"分诊台"**，
判断这活属于哪档，再路由给对应档位的模型：

```
用户请求 → [haiku 分诊：这活难吗？]
              ├─ 简单/批量 → haiku 处理（90% 的流量）
              └─ 复杂/重要 → opus 处理（10% 的流量）
```

伪代码三行就能写，但"分诊判断得准不准"本身是个评测问题——
**分诊台判错了，要么烧钱要么砸活**。等你真做服务时，用第 7 课的方法
给分诊台也建一套测试用例。

## 第 5 章 · 换挡前先立尺子：用评测证明"没降智"⭐

敢换便宜模型的唯一硬依据是**分数**，不是感觉：

```bash
cd /d/studyAi/eval-practice-house
# 1. 把 extractor.py 的 MODEL 换成 haiku → 跑 eval.py，记下分数
# 2. 换回 opus → 再跑一次，对比
```

- 分数基本没掉 → 这类任务放心用便宜的，规则写进你的选用表
- 掉了 → 证明这个任务吃智力，留给贵的——**这条"护城河"本身也是你的选用规则**

这一步就是你第 7 课学的"评测驱动开发"在**成本优化**上的复用：
基线 → 改动（换模型）→ 重跑对比 → 得出结论。一个方法，两个用途。

## 第 6 章 · 在 Claude Code 里换挡（不用写代码的版本）

- 对话中输入 `/model` 随时切换当次会话的模型——**简单会话就别开 opus 烧钱**
- Claude Code 派子代理时可以指定不同模型（第 9 关）——主对话 opus 规划，
  子代理干简单活用低档，就是界面版的第 3 章两段式

## 🎮 闯关任务（3 关）

### 第 1 关 · 换挡实验
按第 2 章改 `agent_lib.py`，同一任务跑 opus 和 haiku 各一次，填完对比表。
**验收**：能说出这个任务上两个模型的差距值不值 5 倍价差。

### 第 2 关 · 两段式流水线
跑通第 3 章的 `two_stage.py`（任务选个真实的小需求，比如"给 cases.json 追加 2 条新用例"）。
**验收**：观察到第 1 段只花 1 次调用、第 2 段跑了多轮工具循环。

### 第 3 关 · 立你自己的选用规则 ⭐
用第 5 章的尺子法，测完写下 3 行"任务 → 档位"规则（格式照第 1 章表格）。
**验收**：规则每条都有 eval 分数背书，不是拍的。

## 速查：任务 → 档位

| 任务 | 默认档 |
|---|---|
| 分类/抽取/格式转换/批量简单活 | haiku |
| 日常写码/文档/一般问答 | sonnet |
| 规划/审查/调试/难题 | opus |
| 极难的长期任务/压轴 | fable（慎重，10× 价格） |

**先跑评测，再定档位——尺子说了算，直觉不算。**
