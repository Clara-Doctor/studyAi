## 第 1 章 · 模型是怎么炼出来的（四个步骤记一辈子）

一个模型出厂前经历四道工序，每道工序都是一个行业黑话高频区：

```
①预训练 → ②微调(SFT) → ③对齐(RLHF等) → ④压缩出厂(量化/蒸馏)
```

| 工序 | 干什么 | 类比 | 黑话|
|---|---|---|---|
| ① 预训练 | 用海量互联网文本练"接话"能力——**学知识** | 读了整个图书馆，但只会续写，不会对话 | base 模型、预训练 |
| ② 微调 SFT | 用人工写的高质量问答对教它"怎么好好回答"——**学格式** | 上岗培训：学会客服腔、分步骤解题 | SFT、指令微调 |
| ③ 对齐 RLHF | 人类给回答打分，模型学会"人喜欢什么样的答案"——**学价值观** | 绩效考核+奖金挂钩，慢慢变"懂事" | RLHF、DPO、对齐 |
| ④ 压缩出厂 | 量化（把参数精度压低换速度）、蒸馏（大模型教出小模型）——**学便宜** | 精装改简装，便宜好卖 | 量化、蒸馏、小模型 |

**程序员需要这个的三种场合**：①看新闻能懂（"XX 发布新 base 模型"）；
②懂"微调"只是第②道工序——教的是格式和习惯，**灌不进新知识**（灌知识走 RAG，
呼应你的选型课）；③买小模型时知道它是"蒸馏+量化"的产物——便宜但也继承了大模型
的一部分短板。

## 第 2 章 · 评测基准（Benchmark）：看懂公开榜单

你建的 eval.py 是**私有尺子**；行业还有一套**公共尺子**——benchmark：
固定考题集 + 自动判分，谁家新模型发布都要晒分。

| 榜单 | 考什么 | 听到时怎么理解 |
|---|---|---|
| MMLU / GPQA | 知识问答、研究生级难题 | "考试型智力" |
| SWE-bench | 真实 GitHub bug 修复 | **编程能力的黄金榜**——你听人说"XX 模型 SWE-bench 70%"就是它能独立修掉 70% 的真实 bug |
| LiveCodeBench | 新出的编程题（防背题） | 防止模型"刷题"作弊 |
| LMArena（大模型竞技场） | 真人盲测两两对比投票 | 群众口碑榜，最难造假 |

**看榜三原则**（防被营销忽悠）：
1. **只看和你的活相关的榜**——你写代码，SWE-bench 比数学榜有意义
2. **警惕"刷榜"**：考题泄露/过度调参都能刷高分——所以要看 LiveCodeBench 这类防背题榜
3. **榜单是必要条件不是充分条件**——榜分高 ≠ 适合你的场景，**你自己的 eval.py
   永远是最终裁判**（这正是你第 7 课学的："别人的标尺不如自己的标尺"）

## 第 3 章 · AI 安全与合规：做 AI 应用的硬约束

### 3.1 安全线（攻防视角）

- **越狱（jailbreak）**：绕过安全训练让模型干坏事——话术层出不穷，是持久战
- **提示注入**（你第 17 关学过）：恶意内容藏在模型要读的资料里——
  防线=权限弹窗+安全训练+**别给 AI 过大的权限**
- **红队测试**：发布前专门雇人/用 AI 攻击自己的模型找漏洞——大厂标配
- 工程师日常三条：**输入过滤、输出审查（判分类模型检查）、权限最小化**

### 3.2 合规线（国内做 AI 应用的硬门槛，扫盲必知）

| 概念 | 一句话 | 对程序员意味着 |
|---|---|---|
| **生成式 AI 备案** | 面向公众的生成式服务要在网信办备案 | 你的产品"上线给公众用"前有行政流程，不是纯技术活 |
| **数据出境** | 用户数据传给境外模型（如 Claude/GPT 官方）受监管 | 国内 ToB 项目常用国产模型/私有化的真实原因之一 |
| **个保法（个人信息保护）** | 收集处理个人信息需合规授权 | 喂给模型的数据要先**脱敏**（姓名/手机号/身份证替换掉） |

**工程师的肌肉记忆**：凡是把用户数据送进模型的代码，先过一遍
"这数据能出门吗？"——不能出门 → 国产模型 API 或私有化（第 5 章正篇讲过 ollama/vLLM）。

## 第 4 章 · 推理性能与成本工程：模型跑起来的经济学

模型回答的过程叫**推理**（inference，注意和"推理模型"的"推理"不是一个词，
后者指长思考）。这块的地基概念：

| 概念 | 一句话 | 为什么和你有关 |
|---|---|---|
| **GPU/显存** | 模型跑在显卡上，模型多大就吃多少显存 | 70B 模型 ≈ 40GB+ 显存——为什么私有化烧钱 |
| **量化** | 把参数从高精度压到低精度（INT8/INT4），显存减半再减半 | ollama 在你笔记本跑大模型的秘密就是它；代价是轻微变笨 |
| **TTFT（首字延迟）** | 从提问到第一个字出来的时间 | 用户体验的核心指标——所以有流式（第 6 章） |
| **吞吐** | 每秒能吐多少 token | 决定"打字机"的速度感 |
| **Batch API** | 不急的批量任务打五折，几小时内返回 | 你第 9 章飞轮批量标注用它能省一半钱 |

**成本三层省法**（你已会两层的理论，这里补齐第三层）：
提示词层省（模型编排✅）、缓存层省（缓存✅）、**推理层省**（量化/小模型/批量 API←本层）。

## 第 5 章 · AI 的能力边界与失败学：知道它哪里会坏

幻觉你早知道。但边界不止幻觉——**五个已证实的弱点**，派活前先过一遍：

| 弱点 | 表现 | 工程对策 |
|---|---|---|
| **长上下文中部遗忘** | 100 页文档塞给它，中间部分记不牢 | 关键内容放开头结尾；或切块检索（RAG） |
| **精确计算弱** | 位数一多的算术/数数会错 | 让它**写代码算**而不是"心算"（这也解释了为什么 Code Execution 是标配） |
| **时效盲区** | 训练截止后的事不知道 | 联网搜索 / RAG / 明确告诉它日期 |
| **长任务可靠性衰减** | 连续干 50 步，越后面越容易跑偏漂移 | 拆小任务（你的任务拆解课）、中途检查点、Goal 式验收 |
| **过度自信** | 不知道的时候不承认不知道，硬编 | system 里写死"没把握说不知道"+ 用你学的裁判抽查 |

**失败学心法**：AI 的弱点高度可预测——**好的 AI 工程师不是赌它行，
而是围绕它的弱点设计防线**（判分器、拆解、检索、代码执行——你学过的每一样都是防线）。

## 第 6 章 · AI 产品体验层：用户"手感"的全部来源

功能一样，手感天差地别。四个体验层关键词（你做板块二毕业项目时会全用上）：

| 体验 | 技术本质 | 用户感受 |
|---|---|---|
| **流式输出（SSE）** | 生成一个词推一个词给前端（打字机效果） | "秒回"的错觉 vs 白屏等 30 秒——同一个模型，天壤之别 |
| **进度反馈** | 长任务显示步骤/进度条 | "它在干活"vs"卡死了" |
| **人机协作点** | 危险操作弹审批（human-in-the-loop） | 可控感——你 21 关弹过几百次的那个窗，就是体验设计 |
| **失败兜底文案** | 挂了给"稍后再试"而非报错堆栈 | 你第 8 章降级链的最后一段 return |

**扫盲结论**：AI 应用开发 = 30% 调模型 + 70% 围绕模型修马路（体验、防线、兜底）
——这解释了为什么板块二的"生产工程化"占了三分之一的篇幅。

## 第 7 章 · 前沿瞭望（知道名字即可，别投入）

| 方向 | 一句话 | 状态 |
|---|---|---|
| Computer Use / 浏览器 Agent | AI 直接操作电脑界面（点鼠标打键盘） | 已产品化但可靠性仍有限 |
| 长期记忆系统 | Agent 跨会话记住你和项目（不是塞上下文） | 各家都在摸索，无标准答案 |
| 多 Agent 协作协议（A2A） | Agent 之间直接通话 | 早期，标准未定 |
| 具身智能/硬件 | AI 进机器人、手机端侧 | 产业早期，程序员可远观 |

**瞭望原则**（呼应正篇 FOMO 解毒剂）：这些方向等你**真实需求出现**再深入；
它们成熟的信号会是"你的主力工具更新了"，而不是你必须提前押注。
