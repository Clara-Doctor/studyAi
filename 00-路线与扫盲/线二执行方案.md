## 一、第一周：RAG 周（关 1~4，约 6~8 小时）

### D1 · 关 1+2：体感 + 相似度（约 2h）
- **做**：
  - 关 1 体感实验：问 Claude "cases.json 第 7 条用例的期望朝向"（不给资料），
    再粘资料问——把两次回答贴进 `notes.md`（15min，零代码）
  - 关 2：抄教程第 2 章 `similarity.py` → 跑通 → **改一次问题**复跑，
    亲眼看关键词法抓瞎（"89㎡南向包入住"）
- **验收**：`python -X utf8 similarity.py` 输出排序分数；能口头回答
  "为什么同义词会失手"
- **commit**：`关2：jaccard 相似度 + 同义词失手实验`

### D2 · 关 3：RAG 机器人（约 2h）
- **做**：抄 `faq.md`（10 条问答）+ `rag_bot.py`（教程第 3 章完整代码）→ 跑通
- **必做实验**：问"停车方便吗"（该命中）、"房东是谁"（该答"没有提到"）
  ——第三条是**反幻觉红线**，答了别的就是失败，回去检查 system 提示词
- **验收**：三个问题的实际回答记录进 notes.md
- **commit**：`关3：房源FAQ问答机器人（含反幻觉测试）`

### D3 · 关 4：调优 + 评测（约 2h）
- **做**：抄 `rag_eval.py`（5 个测试对）跑出基线命中率 →
  依次拧三个旋钮：块大小 / k=3→5 / 标题加权，**每拧一次记一格**
- **验收**：一张"旋钮→命中率"小表（3 行以上，有数字）；命中率 ≥4/5
- **commit**：`关4：检索命中率评测 + 调参记录表`
- **周验收（D3 晚）**：把三个 commit 的输出贴给我 review

## 二、第二周：裁判周 + 生产周（关 5~9，约 6~8 小时）

### D4 · 关 5：写裁判（约 2h）
- **做**：抄教程第 5 章 `judge.py`（工具调用+兜底模式——你写过两遍的老朋友）→
  拿 extractor 的 3 条真实输出（1 好 1 含糊 1 编造）送评
- **验收**：编造那条**必须被打 1 分且理由引用原文**；达不到就修 RUBRIC
- **commit**：`关5：LLM 裁判（工具调用模式）`

### D5 · 关 6：校准裁判（约 1.5h）
- **做**：抄两遍 5 分答案、第二遍注水 50 字 → 送评抓"长度偏好"→
  修 RUBRIC 重测直到分数稳定；再做一次 A/B 对比式打分实验
- **验收**：notes.md 记录"注水前后分数"和"修 RUBRIC 前后分数"
- **commit**：`关6：裁判校准实验记录`
- **周验收（D5 晚）**：review judge.py + 校准记录

### D6 · 关 7+8：给 rag_bot 套盔甲 + 缓存降级（约 2h）
- **做**：
  - 关 7 是复习性质：你的 `call_with_retry` 已在 extractor 验证过——
    这次**自己凭记忆**重写一遍到 rag_bot 的 answer() 上（写完和 extractor 版 diff 对比）
  - 关 8：`cache_demo.py`——dict 缓存 + 降级链（opus→haiku→兜底文案）
- **验收**：缓存命中时第二次调用 0 次 API（print 一行计数证明）；
  故意把 BASE_URL 改错，降级链走通
- **commit**：`关7+8：rag_bot 盔甲复刻 + 缓存降级链`

### D7 · 关 9：日志 + 数据飞轮（约 1.5h）
- **做**：给 rag_bot 加 csv 调用日志 → 跑 10+ 次 → 挑 2 条最差回答 →
  人工写"应命中什么" → **追加进 faq.md**（只加不改）→ 重跑 rag_eval
- **验收**：完成一次完整飞轮：日志→bad case→知识库→分数变化，全程记录进 notes.md
- **commit**：`关9：调用日志 + 首次数据飞轮`
- **周验收（D7 晚）**：review 三个 commit + csv
